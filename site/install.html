Install FoxLoop

Two halves and a cable: a daemon on your computer, an app on the tablet. On Debian, Ubuntu or Fedora the daemon is two packages and needs no build toolchain.

Check these three first

An Android device, ideally with an S Pen

Any Android device that can act as a USB accessory works as a display. For pressure and tilt it needs a Wacom EMR S Pen — Samsung Galaxy Tab S9 FE or newer, S10 FE or newer. Plus a USB cable that carries data, not only charge.

KDE Plasma or GNOME

On Wayland. Nothing else is supported. On KDE you also need krfb, which provides the tool that creates the virtual monitor; on GNOME you need nothing extra.

A GPU that encodes H.264

Through VAAPI — Intel or AMD. NVIDIA does not work this way, and there is no software fallback.

vainfo | grep -E 'VAProfileH264.*EncSlice'

If that prints nothing, stop here — FoxLoop will not run.

Install it

  1. Install the daemon

    Download the two files for your distribution from the latest release, then:

    # Debian / Ubuntu
sudo apt install ./foxloop_*.deb ./foxloop-uinput_*.deb

# Fedora — the [0-9] keeps foxloop-* from also matching foxloop-uinput
sudo dnf install ./foxloop-[0-9]*.rpm ./foxloop-uinput-*.rpm

    On KDE, add krfb as well: sudo apt install krfb or sudo dnf install krfb.

    No package for your distribution? Build from source — it is a Rust build with a handful of development headers, and takes about a minute.

  2. Log out and back in

    This step is not optional and not cosmetic. The pen permission is an access-control entry attached to your session when it becomes active, so it never reaches the session that was already running when you installed it. Skip this and the pen will report position and clicks but no pressure.

  3. Put the app on the tablet

    There is no store listing yet, so the app is built from the repository:

    cd android-client
echo "sdk.dir=$HOME/Android/Sdk" > local.properties
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk

  4. Plug it in

    Connect the cable and unlock the tablet — Android will not hand the connection to an app while the screen is locked. The app opens on its own; there is nothing to launch.

    On KDE the first run shows your desktop's screen-picker dialog once. Choose Virtual-FoxLoopDisplay. The answer is remembered, so it never asks again. On GNOME there is no dialog.

    Then drag a window onto the tablet.

About the one step that needs root

Everything FoxLoop adds to a shared machine is in one package, foxloop-uinput, and that package is a single udev rule. It tags /dev/uinput so that the user holding the active local session gets access to it — which is what lets the daemon create a virtual pen that can report pressure and tilt.

It grants nothing to someone connected over SSH, nothing to a logged-out or inactive user, and nothing to a system service. It is byte-for-byte the rule Steam ships, so on a machine with Steam installed it changes nothing at all. The alternatives it was chosen over — a world-writable device, or adding you to a group that can read every keyboard on the machine — would both have granted far more.

You can decline it. The cost is that the pen falls back to a portal interface carrying no pressure and no tilt, which is most of the point. On a lab or shared machine that tradeoff is genuinely yours to make; the daemon README spells out how.

Nothing else in FoxLoop runs as root. It installs no setuid binary, adds no user or group, and starts nothing at boot.

When it doesn't work

Start with the log. The daemon narrates every stage, tagged by subsystem:

journalctl --user -u foxloop-daemon -f   # if udev started it
foxloop                                  # or run it in a terminal
What you seeWhat it means
failed to open /dev/dri/renderD128 Your user cannot reach the GPU. Add yourself to the render group and log back in. If the node does not exist at all, there is no VAAPI-capable GPU.
The pen does nothing, and the log says /dev/uinput not accessible The uinput rule is not installed, or you have not logged out and back in since. On KDE the daemon falls back to position and clicks only; on GNOME it exits and tells you the fix.
No virtual monitor appears, on KDE krfb is not installed, so the tool that creates the monitor is missing. The log says failed to spawn.
The picker dialog appears every launch The saved answer was revoked. Pick the monitor once more. If it keeps happening, check that a second daemon is not running — the log says so plainly.
Nothing happens when you plug in The udev rule is not installed, or your session is not the active one. Run udevadm monitor while plugging in to see whether the rule fires.
AOA connect failed The tablet is locked, the app is not installed, or the cable is charge-only. Unlock the tablet first — Android will not route the connection to a locked device.
A frozen or black screen after replugging Stale USB data survived the reconnect. The daemon recovers on its own now; if it does not, run it once as FOXLOOP_USB_RESET=1 foxloop.
The tablet mirrors your main display instead of extending it Known, on KDE. Switch it to Extend in System Settings → Display.

The daemon README carries the full detail: every environment variable, the layout of the source, and what each log tag covers.
